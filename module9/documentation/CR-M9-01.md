# CR-M9-01 — Add Overdue Option to the Status Filter

## Change Request Information

- **Change Request ID:** CR-M9-01
- **Title:** Add Overdue Option to the Status Filter
- **Maintenance Type:** Perfective Maintenance
- **Target Version:** 1.1.0
- **Priority:** Medium
- **Status:** Planned

---

## 1. Problem / Opportunity

The current TaskFlow Student Task Management System already identifies overdue tasks and displays an "(Overdue)" indicator beside the due date of applicable tasks.

However, overdue tasks are not currently included as an option in the status filter. Users therefore need to manually inspect the task list to identify overdue tasks instead of being able to filter them directly.

This presents an opportunity to improve the existing filtering capability without changing the existing task data structure or redesigning the system.

---

## 2. Desired Outcome

Add an **Overdue** option to the existing status filter.

When the user selects **Overdue**, the system should display only tasks whose due date has already passed and whose status is not Completed.

The existing Pending, In Progress, and Completed filtering behavior must remain functional.

---

## 3. Acceptance Criteria

### AC-01 — Overdue Filter Option

The existing status filter provides an **Overdue** option together with the existing task status options.

### AC-02 — Correct Overdue Results

When the user selects **Overdue**, the system displays tasks whose due date is before the current date and whose status is not Completed.

### AC-03 — Completed Tasks Excluded

Tasks with a past due date but a status of **Completed** must not appear when the **Overdue** filter is selected.

### AC-04 — Existing Features Preserved

The change must not break existing system functionality, including:

- Add/Create Task
- Display Tasks
- Edit Task
- Delete Task
- Search
- Priority Filter
- Pending/In Progress/Completed Status Filters
- Form Validation
- Delete Confirmation
- LocalStorage Persistence
- Authentication and Session Handling
- Responsive Layout

---

## 4. Priority and Rationale

**Priority: Medium**

The change is classified as a medium-priority improvement because the existing system already identifies overdue tasks, but users cannot directly filter them.

Adding Overdue to the status filter improves task visibility and makes the existing overdue functionality more useful without requiring a major architectural or data-model change.

---

## 5. Affected Areas

### Architecture
The existing task filtering flow will be extended to support the Overdue filter while preserving the current architecture.

### User Interface / Design
The existing status filter UI will receive an additional **Overdue** option.

### Components / Code
The existing filtering logic will be updated to recognize Overdue as a derived filter condition based on the task due date and completion status.

### LocalStorage / Data
No localStorage schema change is expected. Existing task records already contain the required `dueDate` and `status` information.

### Testing
Existing Module 8 automated tests must continue to pass. At least two additional or updated Vitest tests will be created for the Module 9 change.

Manual testing will also verify the Overdue filter and regression of existing functionality.

### Build / CI
The existing Vite build process and GitHub Actions workflow must continue to pass after the change.

### Documentation
Module 9 documentation, updated architecture evidence, test cases, implementation evidence, and release information will be added.

---

## 6. Scope

### In Scope

- Adding Overdue to the existing status filter.
- Filtering overdue incomplete tasks.
- Excluding completed overdue tasks.
- Adding automated tests for the new filter behavior.
- Adding manual test cases and regression testing.
- Updating architecture and project documentation.

### Out of Scope

- Redesigning the TaskFlow interface.
- Changing the task data schema.
- Adding new authentication functionality.
- Changing the existing task CRUD workflow.
- Replacing the existing search or priority filtering system.
- Adding notifications or reminders for overdue tasks.

---

## 7. Compatibility

The change is backward-compatible with the existing task data because it uses the task's existing `dueDate` and `status` properties.

No migration of existing localStorage data is expected to be required.

---

## 8. Expected Risk

**Risk Level: Low to Medium**

The change affects existing filtering behavior, so regression testing is required. However, the implementation is limited to the existing filter logic and UI, with no expected changes to the data schema or authentication system.
